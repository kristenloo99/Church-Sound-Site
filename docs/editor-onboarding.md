# Editor Onboarding (for the deacon and backup editor)

This is the one-time setup. After this, you'll only ever use the
[Content Guide](./CONTENT-GUIDE.md).

## What you'll need

- A computer (any modern laptop)
- An email address
- About 15 minutes

## Step 1: Create a GitHub account (if you don't have one)

1. Go to https://github.com/signup
2. Use your email address.
3. Pick a username (lowercase, no spaces).
4. Set a password and save it somewhere safe (password manager
   recommended).
5. Verify your email.
6. Enable two-factor authentication when GitHub prompts you (very
   important — protects the site).

## Step 2: Get added to the repo

The developer will add your GitHub username as a collaborator on the
church-owned repository. You'll get an email invitation. Click the
"Accept invitation" button.

## Step 3: First login to the admin

1. Go to `https://YOUR-SITE.netlify.app/admin`.
2. Click "Login with GitHub."
3. Approve any permissions GitHub asks for.
4. You should land on the admin home page with a sidebar of content
   types.

If you can't log in, check that:

- You accepted the GitHub repo invitation in step 2.
- You're signed into the right GitHub account (sign out and in if you
  use multiple accounts).
- Two-factor authentication is enabled and your phone is handy.

## Step 4: Trial edit (the most important step)

Before you leave the onboarding session, complete every one of these:

- [ ] Create a new equipment entry (you can delete it after).
- [ ] Edit an existing equipment entry's `public_notes` and republish.
- [ ] Log a new test issue (you can mark it resolved + delete after).
- [ ] Open a suggestion rule, change `lastVerified` to today, save.
- [ ] Upload a scene photo (a phone photo of the board is fine).
- [ ] Check the public site (open in a phone browser) to confirm your
      changes appear within 2–3 minutes.

If anything didn't work, NOW is the time to ask the developer. After
handoff, expect a slower response.

## Step 5: Set a calendar reminder

Add a recurring calendar reminder for the monthly
[review checklist](./review-checklist.md). 30 minutes a month is enough
to keep the site healthy.

## Step 6: Know who to ask

- **For content questions** — the experienced sound reviewer (named in
  `data/reviewers.yml`).
- **For technical problems with the admin or site** — the developer.
  Their contact info is in the repo's README.
- **For permission / billing questions** — the church office.

## What happens if I forget my GitHub password?

Use GitHub's password reset link. Make sure your email on GitHub is
still your current email.

## What happens if I leave the church?

Notify the deacon (or developer) so they can remove your access. The
content stays — only your edit permissions are removed.
